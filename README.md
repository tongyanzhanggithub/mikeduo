## 这是什么

**觅客舵（MiKeDuo）** 是一个装在自己电脑上的外贸获客工作台，Electron 桌面应用，Windows x64。

一条完整的获客流水线：

```
输入产品和市场
   ↓
AI 联网找真实进口商 ─────────────→ 线索池（质量分 A–D）
   ↓                                    ↓
补全并验证采购人邮箱 ←─── 真实源 / AI 推测 / 规则兜底 三级
   ↓
生成个性化开发信序列（首封 / 价值 / 案例样品 / breakup 四封）
   ↓
发送预检（✓ 可发送 ｜ ⚠ 提示 ｜ ⛔ 阻断）→ 你审批 → 发出
   ↓
客户回信自动进统一收件箱 → 意图识别 / 风险扫描 / AI 回复建议
   ↓
CRM 六阶段推进 → 报价单 → 成交
```

**AI 干活，人拍板。** 发送这一步永远等你点最后一下——这是设计，不是没做完。

## 它解决什么问题

| 痛点 | 现状 | 觅客舵的做法 |
|---|---|---|
| 平台年费两三万，换来一堆比价询盘 | 被动等询盘 | 一次买断，主动开发 |
| 开发信发了几百封像扔进黑洞 | 90% 压根没进收件箱 | 强制邮箱验证 + 强制域名预热，把送达当生死线 |
| 客户资料躺在别人服务器上 | 云端 SaaS，断续费清零 | 全部数据只存本机，开发者也访问不到 |
| 买了工具不会用 | 文档一堆没人看 | 引导五步与配套课程同构，每步说清做什么/为什么/做完看到什么 |

**诚实边界**：不做自有买家数据库、不做团队协作、不做托管发信基础设施。这三项走"接第三方 + 教配置"路线绕开。

## 官网抓取实测覆盖率

这个数字撑着「第一封信不用配任何 key」这个说法（见下面「要花多少钱」），所以**实测过，不是估的**。

样本 20 个真实海外买家官网，用产品自己的方法生成（搜「进口商/经销商 + 品类 + 市场」
取结果里的公司官网），覆盖 6 个品类 × 6 个市场：无人机配件·阿联酋、汽配·肯尼亚、
LED·越南、水泵·尼日利亚、包装机械·巴西。

| 指标 | 实测 |
|---|---|
| 域名能打开 | 80%（4 个打不开：3 个域名已注销、1 个超时） |
| **拿到邮箱**（占能打开的） | **68.8%** |
| 拿到同域邮箱 | 62.5% |
| 拿到电话 | 81.3% |
| 拿到 WhatsApp | 43.8% |
| **邮箱或电话至少一个** | **93.8%** |
| 拿到官网事实（写开发信用） | 100% |
| 动态渲染抓不到的站 | **0%** |

三条值得说的：

- **电话覆盖率（81.3%）比邮箱（68.8%）高**，WhatsApp 也有 43.8%。中小买家官网上
  留电话比留邮箱更普遍——对外贸来说 WhatsApp 本来就是主渠道，这条路不该被忽略。
- **一个动态渲染站都没有。** 发展中市场的中小进口商官网基本是老派静态 HTML，
  所以「SPA 抓不到」这个担心在这个客群里几乎不成立。
- **明文邮箱（54.5%）比 mailto 链接（45.5%）还多**——只认 `mailto:` 会漏掉一半。

> 样本只有 20 个，置信度有限，但足以说明 ≥60% 站得住。
> 复现：`node tools/coverage-test.mjs 你的清单.txt`

## 三条写进代码的铁律

这三条是产品的口碑防线，**做成了不可关闭**：

### 1. 没验证过的邮箱发不出去

邮箱来源是 AI 或规则推测、又没通过验证的线索，草稿照常生成并留在待审批里，但**永远走不到"待发送"**。批量审批、到期发送、自动驾驶、Webhook 派发全部经过同一个闸门 `preflightOutboxItem`。

⛔ 徽章可以点开，里面写清"这在保护你什么"，并直接给三个修复入口：立即验证这条 / 批量验证全部待验证(N) / 我确认无误标记人工核实（危险样式二次确认 + 永久留痕，导出可见）。

> 向未验证邮箱发信会推高退信率，退信率超 5% 就会被判定为垃圾发送者——整个发信域名废掉，以后给老客户发报价单都进垃圾箱。

### 2. 新域名前 14 天硬顶 20 封/天

预热起点按**第一封真实发出的邮件**反推，改配置绕不过去。发信队列顶部有一条**起航航程条**：D1–D14 虚线航线、一枚小船停在当天、下面标"今日限额 8/20 封"，把"被限制"翻译成"在航行"。第 15 天收成顶栏一枚绿锚。

> 软件卡的是合规底线 20 封；配套课程教的是第 1 周 ≤10 封的最佳实践。两者并存不冲突。

### 3. 发送永远等人工审批

自动驾驶会把线索处理、补全、验证、入队、生成 AI 草稿全做完，但**停在待审批**。WhatsApp 冷发（没有邮件往来记录就直接发）每次都弹风险确认，不可关闭。

## 要花多少钱

买断价之外，软件本身不再收任何费用，也不抽成。但有些环节要调第三方接口，
那笔钱你直接付给服务商——所以**先把哪些免费、哪些要钱说清楚**。

| 环节 | 花费 | 说明 |
|---|---|---|
| 粘贴搜索结果找公司 | **免费** | 手动搜、整页粘，不用任何 key |
| 抓官网拿真实联系方式 | **免费** | 实测 20 家里 15 家能拿到邮箱或电话 |
| 合规筛查 · HS 校验 · 域名体检 | **免费** | 名单随包内置，本机跑，不联网 |
| 内置收发信（SMTP/IMAP） | **免费** | 用你自己的企业邮箱 |
| AI 细化定位 / 写开发信 / 读回复 | ≈ **¥14/月** | 配一个 DeepSeek key 就够日常量 |
| 一键起量（自动搜，不用手动粘） | 按次 | SerpAPI 每月 100 次免费，之后 $50/月起。**不配也能用**，只是要自己粘 |
| 邮箱验证（Hunter 等） | 按次 | 可选。官网抓取 + 本地 RCPT 探测已能覆盖多数情况 |

**所以「发出第一封信」这条路是真的不用配任何 key**：粘贴搜索结果 → 抓官网拿联系方式
→ 填自己的邮箱授权码 → 发出去。上手向导的五步就是这条路。

要跑量、要 AI 帮你写信读信，才需要配一个便宜的 key。

> 没有「内置额度」这种东西。软件是买断的、跑在你自己电脑上，我们没法替你垫接口费；
> 也不会把我们自己的 key 打包进安装包——`.asar` 可以解包，那等于把 key 送给所有人。

## 我们不做什么

一个什么都说自己强的产品，用户反而不信。这几件事我们**明确不做**，
不是还没做，是想清楚了不做：

### 不自带买家数据库

同类产品主打"3 亿条海关记录，开箱即用"。我们没有，也不打算有——
持续采购和更新数据是**订阅制才养得起的成本结构**，买断制养不起。
硬撑的结果只有两个：要么涨价变成年费，要么数据越来越旧。

我们给的是另一条路：抓官网、粘贴搜索结果、接你自己的 SerpAPI / Hunter、
导入**你自己买的**海关数据 CSV（`electron/customs.js` 支持）。

### 不做多账号和团队协作

单机买断、数据只在你的电脑上——这两件事和"多人共享客户池、分配任务、
避免撞单"在架构上是冲突的。做半吊子的协作不如不做。
真要在两个人之间传客户，用「导出客户包」。

### 不承诺任何商业成果

界面上不会出现"成交概率""预计回复率提升 40%""ROI 1:2300"这类数字。
线索有优先级分，但那是**排队顺序，不是成交预测**。
详见[用户协议与免责声明](docs/用户协议与免责声明.md)。

### 不编造任何联系人

拿不到就显示「待查联系人」，不会用 `firstname.lastname@domain` 拼一个给你。
理由不是清高——**拼出来的地址退信率极高，退信率一高你的发信域名就废了**。
联系人只有三个合法来源：官网公示（抓取，带出处链接）、真实源（Hunter /
邮箱查找 Webhook）、AI 联网核实（必须给 `source_url`）。

## 商业化基建 F1–F9

| | 功能 | 关键实现 |
|---|---|---|
| **F1** | **离线激活码** | Ed25519 非对称签名，**全程不联网**。机器码 = CPU ID + 主板序列号 + 系统盘卷序列号 → SHA-256 前 16 位。激活信息用 Electron `safeStorage` 加密写盘；文件损坏或被改则静默回退试用，不崩溃 |
| **F2** | **试用模式** | 线索池**存量**硬上限 20 条，7 条入池路径统一走 `admitProspects` 一个闸门；导出加水印；云端大模型区锁定态展示（不隐藏）；激活后角标/水印/AI 区**三联动**即时解锁，不用重启 |
| **F3** | **未验证邮箱强制拦截** | 见上文铁律 1，独立 `sendGuard` 模块 + 21 项单测 |
| **F4** | **诊断日志与错误兜底** | 主进程/渲染/unhandledrejection 全捕获；错误页第一句先说"你的数据是安全的"；200 条操作环形缓冲；邮箱打码、电话留国家码+末两位、**零邮件正文**；文件 <2MB |
| **F5** | **自动更新** | electron-updater + GitHub Releases，顶栏蓝点非阻断；激活签发超 365 天提示续费但**不影响使用** |
| **F6** | **新手引导对齐课程** | 五步与课程同构，横向步骤条可折叠；第 4 步主按钮是「**先发一封给自己**」——走真实发送链路完成自发自收闭环 |
| **F7** | **数据自动备份** | 每日首启导出全量 JSON 到 `userData/backups/`，滚动保留 14 份；恢复前预览数据规模，**覆盖前自动再备份一份** |
| **F8** | **合规与限流** | 欧盟活动退订元素模板级注入，删掉预检 ⛔；一次性 GDPR 提示（带"不再提示"勾选）；域名预热硬顶；WhatsApp 冷发确认 |
| **F9** | **品牌化** | 应用名 / 图标（纯 JS 生成 16/32/48/256）/ 窗口标题 `觅客舵（试用版） · 活动名` / 安装包名；关于页含版本、激活状态与档位、机器码、更新到期日、客服微信；首启强制勾选《许可与免责声明》 |

## 快速开始

### 用户侧（装好就用）

下载 `MiKeDuo-Setup-v1.0.0.exe` 双击安装 → 桌面出现带 M 图标的「觅客舵」→ 打开即用。首次启动会让你勾选《许可与免责声明》。

### 开发侧

```bash
git clone https://github.com/tongyanzhanggithub/mikeduo.git
cd mikeduo
npm install                # 首次，会下载 Electron 二进制（约 110MB）
npm start                  # 以桌面应用窗口打开
```

改完代码：

```bash
npm run build              # src/*.js → app.js，并自动打版本戳防缓存
```

打安装包：

```bash
npm run dist               # 内含 build，产物在 dist-desktop/
```

其它命令：

```bash
npm test                   # 29 项单测（激活码 10 + sendGuard/试用/合规/脱敏 19）
npm run test:desktop       # 7 项真 Electron 集成测（机器码/safeStorage/落盘/备份滚动）
npm run icon               # 重新生成 icon.ico / icon.png / favicon.png
```

> **浏览器轻量模式**：在项目目录跑 `python -m http.server 4174`，然后打开 <http://localhost:4174/>。端口必须固定。
> 这个模式读不到机器码，**永远是试用态**，只适合体验。真干活请用桌面版。两者数据空间独立。

## 第三方接入

觅客舵**自己不抓数据、不提供发信服务**。找客户与验邮箱走你配置的第三方服务；发信收信用**你自己的企业邮箱账号**。

### 直连（推荐，不用装 n8n）

四样东西填完，整条链路就通了：

| | 干什么 | 要填 | 在哪 |
|---|---|---|---|
| 发信 SMTP | 把审批过的邮件真发出去 | 主机/端口/账号/**客户端授权码** | 设置 → 收发信 |
| 收信 IMAP | 客户回信自动进统一收件箱 | 主机/端口/账号/**客户端授权码** | 设置 → 收发信 |
| SerpAPI | 联网找真实进口商 | API Key ×1 | 设置 → 数据源 |
| Hunter | 补全采购人邮箱 | API Key ×1 | 设置 → 数据源 |

- **SMTP/IMAP 密码**用 Electron `safeStorage` 加密存本机，**渲染层拿不到、备份 JSON 里也没有**
- **API Key** 存在本机数据里，但**导出备份时会自动抹掉**——备份可以放心发给客服，换机恢复后重填一次即可
- 每项都有「测试连接」，失败时给的是"你该改什么"而不是原始报错（`535 authentication failed` → "多半是填了登录密码而不是授权码"）
- Hunter 返回的低置信度地址（<80）会被标为**推测**而不是已验证，照样过不了发送闸门
- **退信自动识别**：收信时先认出退信与自动回复（不让它们变成"客户回信"），硬退信（5.x.x 地址不存在）立即拉黑保护发信域名，软退信（4.x.x 暂时失败）只标记
- **每日用量上限**：SerpAPI / Hunter 按次计费，自动驾驶会在后台静默调用，各设一个每日上限（默认 50 / 100）免得额度被悄悄烧光

> **90% 的配置失败都是同一个原因**：SMTP/IMAP 填的是登录密码，不是**客户端授权码**。
>
> ⚠️ **Gmail / Outlook 用不了直连**——这两家已强制 OAuth2。填了会被识别出来并给出提示，建议改用企业邮箱（腾讯/网易/阿里企业邮都支持授权码），用自有域名发信本来也更专业。

### Webhook（进阶 / 自定义）

要对接自有系统、非标数据源，或想用 n8n 编排全流程时才需要。7 个可选：

| Webhook | 什么时候还需要它 |
|---|---|
| 搜索采集 | 想用 SerpAPI 以外的数据源（海关数据商、自有数据库） |
| 邮箱查找/验证 | 想用 Apollo / Dropcontact 等 Hunter 以外的服务 |
| 发信 / 拉取回复 | 用 Gmail/Outlook（需 OAuth），或要在 n8n 里做额外处理 |
| **CRM 同步** | **没有替代路径**——每家 CRM 接口都不同，只能自己编排 |
| WhatsApp / 发送状态回传 | 可选 |

直连与 Webhook **可以逐项混用**：发信收信走直连、找客户走 SerpAPI 直连、CRM 同步走 n8n，完全没问题。

**AI 引擎**在「设置 → AI 引擎」里选：Claude / OpenAI / DeepSeek / 通义千问 / Kimi / 智谱 GLM，或填任意 OpenAI 兼容接口。意图识别、回复建议、深度写信由所选模型完成，未配置或调用失败自动降级本地规则。「联网找客户」依赖 Claude 内置联网搜索（也可改配 SerpAPI 直连）；「竞品反查 / 官网深挖」只需读已知网址，桌面版自行抓页面后交任意模型解析，不限服务商。

## 激活体系怎么运转

```
你（开发者）                            用户机器
─────────────                          ─────────────
私钥 tools/keys/private.pem              硬编码公钥验签
        │                                      ▲
        │ node tools/gen-key.mjs <机器码> <档位> │
        └────────── 激活码（14 段×8 位）────────┘
                                               │
                                    比对本机机器码 → safeStorage 加密落盘
```

**首次准备（只做一次）**

```bash
node tools/init-keys.mjs      # 生成密钥对，公钥自动回写 electron/license.js
```

**日常发码**

```bash
node tools/gen-key.mjs 7F3A-K2M9-QX41-B8CD pro
# 档位：basic 基础版 / pro VIP版 / coach 陪跑版
# 签发日决定"首年免费更新"的到期时间，省略取今天
```

每次出码会往 `tools/keys/issued.log` 追加一行流水，核对订单和查重都靠它。

> ⚠️ **`tools/keys/` 已被 `.gitignore` 排除，不在本仓库内。**
> 私钥泄露 = 任何人都能自己造激活码。务必离线备份两份，绝不进 git、绝不外发。
> 换机、一码两机的处理流程见 [激活系统运维说明](docs/激活系统运维说明.md)。

**为什么激活码是 14 段而不是更短**：Ed25519 签名固定 64 字节，base32 后就是 100+ 字符。截断签名会导致完全无法验签，只能改用对称密钥——那等于把密钥打包进应用，谁都能造码。码是复制粘贴给用户的，长度不影响体验，输入框已做粘贴自动清洗（空格换行去掉、O/0 与 I/1 自动纠正）。

### 为什么是"拼接"而不是 ES 模块

整个应用共享一个全局作用域，很多顶层代码（`VIEW_RENDERERS`、初始化调用）依赖"同一脚本内函数声明整体提升"。拆成多个 `<script>` 会打断跨文件提升而报错；改 ES 模块要给上百个函数逐个加 `export/import`。按顺序拼接可以 100% 保持原有运行语义。

### 08 对既有函数的增强约定

商业化代码集中在两个文件，**不散改 01–07**。增强一律"包一层"：

```js
const __mkdBasePreflight = preflightOutboxItem;
preflightOutboxItem = function (item) {
  const result = __mkdBasePreflight(item);   // 先跑原逻辑
  /* 再加自己的判定 */
  return result;
};
```

目前包了：`render` / `download` / `aiEnabled` / `addLog` / `preflightOutboxItem` / `preflightBadge` / `queueProspect` / `remainingDailyQuota` / `deliverApprovedWhatsapp` / `ingestInboundMessage` / `runOneClickPipeline` / `markProspectOptOut`；`renderChecklist` 用同名重声明覆盖。

> ⚠️ **08 里的模块级 `const` 不能被首屏渲染读到**（那时还在 TDZ）。凡是会被首屏渲染链路调到的数据，写成函数返回（例如 `onboardingSteps()`）而不是常量。

## 数据存在哪、安不安全

- **全部业务数据只存本机**：桌面版在 `%APPDATA%\觅客舵`（菜单 `文件 → 打开数据存放位置` 可直达），浏览器模式在 localStorage。开发者访问不到，也没有任何服务端。
- **激活信息**用 Electron `safeStorage` 加密写入 `license.dat`，明文不落盘。
- **自动备份**每天首启一份全量 JSON 到 `userData/backups/`，滚动保留 14 份。
- **诊断日志**导出前脱敏：邮箱 `a***@d***.com`、电话只留国家码+末两位、**不含任何邮件正文**，可以放心发给客服。
- **API Key**（AI 引擎 / SerpAPI / Hunter）只存本机、随请求直连服务商，不经过任何第三方；**导出备份时会自动抹掉**，备份 JSON 可以放心发给客服，换机后重填一次即可。
- **SMTP/IMAP 密码**级别更高：由主进程用 `safeStorage` 加密存 `mail.dat`，界面读不到、备份里也没有。
- **海关提单库**存 `userData/customs.jsonl`，只在本机查询、不上传、不进备份。软件**不提供整库导出**——多数数据商允许订阅者自用、禁止再分发，留个导出口就等于给再分发开通道。

## 已知限制

- **仅 Windows x64**。Mac 版在路线图上，未开始。
- **自动驾驶是应用内的定时器**。「设置 → 后台运行」可开启托盘常驻与开机自启，关掉窗口后仍继续跑；但机器关机就停。要真正 7×24 无人值守得把采集/发送放到 n8n + 外部 cron。
- **自动更新的"静默下载新版本"尚未在真实 release 上验证**——需要先配好 `build.publish` 并发一个 GitHub release。更新失败不影响使用这条已实测成立。
- **激活是"防君子"**。真正的护城河是课程更新、学员群和答疑，不是这段代码。
- **视觉方向已与原产品设计文档分叉**：文档 B2/B3 写的是"舵轮 + 深海蓝 + 航标橙"的远洋航务感；当前代码走的是 **light AI assistant 方向**（蓝绿渐变 M 标、浅色侧栏、`--ai` 系列令牌）。功能与页面结构仍按文档实现，只有品牌与色板换了方向。
- 一码两机由开发者侧登记表人工控制，**应用侧不做联网校验**。
