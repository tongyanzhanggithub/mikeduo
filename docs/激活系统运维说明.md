# 觅客舵 · 激活系统运维说明

> 给你自己看的。用户永远不会看到这份文档。

---

## 1. 它是怎么工作的

离线非对称签名，**全程不联网**：

```
你（开发者）                          用户机器
─────────────                        ─────────────
私钥 private.pem  ──签名──▶  激活码  ──▶  公钥（硬编码在应用里）验签
（只在你本机）                              ＋ 比对本机机器码
                                            ↓
                                    safeStorage 加密写 license.dat
```

- **机器码**：CPU ID + 主板序列号 + 系统盘卷序列号 → SHA-256 → 前 16 位 → `XXXX-XXXX-XXXX-XXXX`
- **激活码**：`版本(1B) + 档位(1B) + 签发日(2B) + Ed25519 签名(64B)` → base32 → 14 段 × 8 位
- **签名对象**：明文 `机器码|档位|签发日`。换机器 → 验不过；改档位或日期 → 验不过；伪造 → 需要你的私钥

> **为什么激活码是 14 段而不是 5 段**：PRD 界面草图画的是 5 段 25 位（125 bit），装不下 Ed25519 的 64 字节签名。要么把签名截断（等于把非对称签名降级成"看起来像"），要么让码长一点。选了后者——码是复制粘贴给用户的，长度不影响体验，输入框已做粘贴自动清洗。

## 2. 首次准备（只做一次）

```bash
node tools/init-keys.mjs
```

- 生成 `tools/keys/private.pem`（私钥）与 `public.pem`
- 自动把公钥回写到 `electron/license.js` 的 `PUBLIC_KEY_B64`
- `tools/keys/` 已在 `.gitignore` 里

**私钥必须做的三件事**：

1. 离线备份两份（U 盘 + 加密网盘），丢了 = 所有老用户换机后无法补发新码
2. 绝不进 git、绝不发给任何人、绝不放在会同步的目录里明文存
3. 换机换电脑时手动拷过去，不要图省事重新生成

> `node tools/init-keys.mjs --force` 会重新生成密钥对，**已发出的全部激活码当场作废**。除非私钥泄露，否则永远不要跑。

## 3. 日常发码（付款后 2 小时内）

用户回传机器码后：

```bash
node tools/gen-key.mjs 7F3A-K2M9-QX41-B8CD pro
```

参数：

| 位置 | 值 | 说明 |
|---|---|---|
| 1 | 机器码 | 用户从「激活」弹窗复制的，带不带横杠都行 |
| 2 | 档位 | `basic` 基础版 ¥699 ／ `pro` VIP版 ¥1499 ／ `coach` 陪跑版 ¥4999 |
| 3 | 签发日（可选） | `YYYY-MM-DD`，省略取今天。**决定首年免费更新的到期日** |

输出里同时给出更新服务到期日，直接抄进发货消息。每次出码都会往 `tools/keys/issued.log` 追加一行流水（时间 / 机器码 / 档位 / 签发日 / 激活码），核对订单和查重都靠它。

**发货话术模板**：

> 激活码来了，复制整段粘进「激活」弹窗即可（空格换行会自动清理）：
> `AFIASZJR-2722H5UJ-…`
> 档位：VIP版 ｜ 更新服务至 2027-08-02
> 一码可绑两台设备，第二台在那台电脑上重复一次「发机器码 → 我发码」就行。

## 4. 一码两机怎么控

**应用侧不联网校验，所以两台机的限制靠你的登记表把关**，不是靠代码。

订单表（飞书多维表格）字段：日期 / 微信昵称 / 金额 / 档位 / 机器码1 / 机器码2 / 激活码1 / 激活码2 / 发货状态 / 备注 / 退款标记。

- 第一次发码 → 填机器码1
- 用户申请第二台 → 核对是同一个买家 → 填机器码2，再出一次码（同档位、同签发日，保证更新到期日一致）
- 申请第三台 → 先问原因。换机走第 5 节，加设备要补款

## 5. 换机处理

用户重装系统一般机器码不变（CPU/主板/卷序列号都没换）；换硬件或换电脑就会变。

1. 让用户在**新机器**上打开应用，复制新机器码
2. 核对订单表里的历史机器码与买家身份
3. 在备注里把旧机器码标记为「已作废（换机 YYYY-MM-DD）」
4. 用新机器码出码，**签发日沿用首次购买日**——换机不该重置更新服务年限
5. 提醒用户：旧机器上的数据要用「设置 → 数据与备份」导出 JSON，在新机器导入

> 老码不会被"吊销"，旧机器还能继续用。这套是防君子不防小人，真护城河是课程更新、群和答疑。

## 6. 排查

| 用户报的现象 | 大概率原因 | 处理 |
|---|---|---|
| 提示「激活码格式不对」 | 抄漏了一段 / 只复制了半截 | 让他重新整段复制粘贴，别手打 |
| 提示「与本机不匹配」 | 机器码发错（发的是别的电脑的）／ 你出码时抄错机器码 | 让他重新截图机器码，比对 issued.log |
| 连续 3 次失败 | 弹窗会自动露出你的客服微信 | 让他把机器码截图发过来，你现场出码 |
| 「验证通过但写入失败」 | userData 目录权限异常 | 让他用管理员身份启动一次 |
| 激活过，重开又变试用 | license.dat 被清理软件删了 / 硬件变了 | 重新粘一次激活码即可（码没作废） |

诊断信息在「设置 → 授权、备份与诊断 → 导出诊断日志」，里面有机器码、授权状态与最近 200 条操作，邮箱电话已打码。
