# 觅客舵 · 完整功能清单

> 本文件是 README 拆出来的**业务功能全量清单**，逐条列出这套系统已经具备的能力。
> 想快速了解项目请看 [README](../README.md)；想知道与产品设计文档的对齐情况请看 [设计文档核对表](设计文档核对表.md)。

## 已具备

- AI 自动获客 Agent：用一句话下达开发任务（如"帮我找美国和加拿大做户外家具批发的进口商，规模 20 人以上，自动发开发信和 WhatsApp"），系统解析为任务卡片（Claude 或本地规则），确认后自动执行 寻客漏斗（抓取→画像匹配→验证→去重→评分入围）→ 触达审批（逐条 / 批量抽审 / 全自动三种模式）→ 自动开发（AI 初轮应答标准问题、敏感话题转人工、opt-out 即时黑名单、全程留痕）→ 意向分级移交（🔥热=询价要样及转人工立即接管、🌤温=培育、❄️冷=换角度或黑名单），并按市场回复率给出"效果回流"倾斜建议。
- 开发活动配置：产品、目标市场、客户类型、卖点、认证、署名和每日开发上限。
- 搜索自动化：按进口商/经销商、批发目录、采购负责人、LinkedIn、零售商供应商入口、协会名录、海关数据、竞品渠道生成搜索任务。
- 搜索结果导入：粘贴公司官网、Google 结果、LinkedIn 公司页、邮箱、电话或 CSV 行，自动解析为待审核线索。
- 海关提单 CSV 导入：粘贴 ImportYeti / ImportGenius / Volza / 腾道 等平台导出的提单 CSV，自动识别（认收货人列 + 发货人/HS/提单号/到港日等佐证列）并按买家聚合——同一家公司的多条提单合并成一条线索，进口条数、最近到港日、HS 编码、现有供应商家数写进采购信号。自动处理真实数据里的几种脏：地址列内的逗号（认双引号包裹）、`C/O 货代` 后缀（并回主记录）、`TO ORDER` 等占位收货人（剔除）、全大写公司名（转正常大小写）。目的国列优先于原产国列（原产国是中国，不是买家所在地）。「海关数据示例」按钮可填入一份样例先跑通流程，样例文件见 [样例-海关提单数据.csv](样例-海关提单数据.csv)。
- 批量解析官网（海关数据必经的一步）：海关提单只有公司名没有域名，而找联系人、官网深挖、邮箱模式推测全都要域名。潜客队列的「批量解析官网」用 AI 把公司名+国家解析成官网域名，Claude 走联网核实（标"联网核实"），其它模型为推测（标"AI 推测"）。**找不到就留空并标"未找到"，绝不用规则凭空拼域名**——拼错的域名会让后续所有推测邮箱指向另一家公司。「批量补全联系方式」会先自动跑这一步。
- 潜客队列：管理公司、市场、网站、来源、角色、评分、采购信号、审核状态。
- AI 客户评分：按官网真实性、联系方式、采购信号、客户类型和互动信号（回复/打开/触达）加权计算成交概率，输出 A/B/C/D 优先级与可解释的因子明细。
- 质量分排序与一键入队：潜客队列可按质量分/最新/市场排序、按 A/B/C/D 质量分筛选，顶部有各级数量概览；「一键入队优质客户」把所有 A/B 级、有联系方式、未入队/未回复/不在冷却的优质客户一次性加入触达队列（按钮实时显示可入队数量，首封仍待你审批发送）。
- 批量审批发送 + 发送预检：发信队列每封待发/待审批邮件都带发送预检徽章——⛔ 阻断（客户已退订 / 在退订黑名单 / 邮箱缺失无效）、⚠ 提示（邮箱为推测未验证、含敏感话题账期折扣独家、疑似重复触达）、✓ 可发送；顶部「全选待发 + 批量审批发送」一次勾选多封，点一下只发送预检通过的，阻断项自动保留并提示需修复，把"逐封审批"变成"一屏批量过一遍再发"。
- 发送安全阀：发送环节强制执行邮件日限（管理→规则 emailDailyLimit 与活动日上限取小），超额部分自动保留次日再发；新域名起量期单日大批量会收到预热提示（前 1-2 周建议 ≤20 封/天逐步加量），保护发信域名不进垃圾箱黑名单。
- 持久退订黑名单：客户回信退订（无论是否开启 AI 自动应答）即按邮箱+域名进独立黑名单，清空线索池/重建活动都不丢；联网搜索/粘贴导入再遇到同域名不进池，入队与发送预检双重拦截。
- 线索记品类：每条线索入池时记住所属品类，四品类并行开发时，跟进信/自动应答/知识库按线索自己的品类选话术，切换活动模板不会串。
- 多语言首封：非英语市场首封自动加当地语言开场（南美西语/巴西葡语/中东阿语/西非法语/独联体俄语/越南语/印尼语/土耳其语共八语，正文英文并注明可用当地语言沟通）；产地按各语言语法拼接（葡语 da China、法语 la Chine、俄语第二格、土耳其语 Çin'in … şehrinden），城市名一律保持拉丁写法不做音译；「Claude 深度写信」按市场商务语言撰写正文并附英文对照。
- 常用出口品类一键模板：控制台开发活动卡顶部内置「摩托车 & 配件 / 汽车零部件 / 笔电 & 电子 / 机械 & 装备」四个常见出口品类，点一下自动填好整套开发活动（产品、目标市场、客户类型、卖点、认证——卖点为地域中立的通用表述如"OEM 级质量/整柜混装/OE 交叉参照"，你自己的产业带背书写进卖点框即可），随后直接「一键起量」联网找对应海外买家。
- 所在城市 / 产地：开发活动卡里填你的城市（如 Ningbo / Foshan / Chongqing），开发信首句、主题行、WhatsApp 首条、四语言开场里的"我们在哪"全部取这个值；留空则一律只说 China。软件不预设任何产业带，不会替你认领不属于你的供应链。
- 具体产品聚焦（AI 细化定位）：品类是"泛"的，真实打法是一个具体零件/小设备打一个市场。在品类芯片下输入你真正要卖的具体产品（可中文，如"CG125 缸体套件""小型制砖机"），点「AI 细化定位」——Claude 产出标准英文行业叫法、2-4 个同义词/别称、HS 编码、该产品的真实买家画像、搜索关键词和针对性卖点；随后搜索式自动变成同义词 OR 组、联网找客户只找"采购这个具体产品"的公司、开发信主题和正文直接点名该产品（保留品类级卖点如 SONCAP/整柜混装）。未配 Claude 时按原文聚焦。聚焦随活动保存，多活动切换不丢。
- 细化已织入自动流程：①「一键起量」时若填了具体产品且尚未细化，自动先跑 ⓪ 细化定位再找客户；② AI Agent 用一句话下任务（如"找尼日利亚买植保无人机桨叶的进口商"），确认任务时自动把任务里的产品做细化（术语/同义词/HS/买家画像并入搜索关键词）；③ 周期补量与自动驾驶复用同一套聚焦搜索，细化一次全程受益。
- 产品级买家画像（按产品精细化获客）：AI 细化定位除术语/同义词/HS 外，还产出①**细分买家段**（2-4 个真实采购该产品的公司类型，各带搜索词）、②**终端用途/关联品**搜索词、③**排除的非买家**类型、④判断一家公司是否真买这个产品的**契合信号词**。这套画像驱动四处：搜索式按每个买家段+终端用途各撒一网、并把排除词并入 Google 取反；联网找客户提示要求覆盖每个买家段并排除非买家；**质量分新增"产品契合度"因子**——命中产品/买家段/用途信号加分（高度契合 +16），撞排除词且无产品信号判"疑似不匹配"减分，A/B/C/D 直接反映"这家是否真买你这个具体产品"而非泛信号；确认闸门弹窗一并展示买家段与排除项。画像随活动保存，多活动切换不丢。
- 细化确认闸门：一键起量前把 AI 细化出的英文术语/同义词/HS/买家画像弹窗给你确认一次（定位错整条链全歪），同一产品确认过不再问；确认状态随活动保存。
- AI 应答试运行模式（默认）：开启初轮自动应答后，AI 起草的应答先以「AI 应答草稿」进队列（邮件待审批 / WhatsApp 待确认）等你审批发送；在 Agent 面板勾选「直发模式」后才直接发送。敏感话题转人工、opt-out 黑名单等护栏两种模式下都生效。
- 真实回信接入（拉取回复 Webhook）：设置里配置后，收件箱「拉取回复」按钮或自动驾驶（每分钟一次）从你的 n8n/IMAP 收件服务拉真实客户回信；按邮箱/公司名匹配线索，匹配不上自动补建「回信导入」线索绝不丢信；入库即联动回复即停、退订黑名单、意图推进 CRM、风险扫描与 AI 应答。接口规格与 n8n 示例见「拉取回复接口」。
- 数据安全：保存加了保护（localStorage 满时不再静默失败，明确提示先备份再清理）；设置页「数据与备份」面板显示存储占用/上次备份时间/数据规模并可一键备份；超 7 天未备份开屏提醒；检测到第二个标签页在改数据时弹红色横幅防互相覆盖。
- 本地部署（两种）：① 桌面应用版（推荐）——Electron 壳，`npm install` 后 `npm run dist` 打包出 Windows 安装包（或 `npm start` 直接以应用窗口打开），双击图标像真软件一样用、不绑端口、不占浏览器；② 轻量版——在仓库目录跑 `python -m http.server 4174` 后用浏览器打开（端口必须固定为 4174）。两者数据空间独立，搬迁走「设置 → 数据与备份 → 导出/导入」。详见「本地部署说明.md」。
- 数据与备份：设置页显示存储占用与上次备份时间，超 7 天未备份开屏提醒；「导出全部数据」存 JSON，「导入备份」一键恢复（换机/换用法时搬数据）。
- 品类专属开发信：套用某个品类模板后，生成的开发信序列（首封 + 价值跟进）自动换成该品类买家最关心的专门英文话术——摩托配件（CG125/GN125 等常见车型、CCC/SONCAP、整柜混装、FOB 报价）、汽配（IATF 16949、OE 交叉参照、售后覆盖）、电子（ODM/OEM、CE/FCC、稳定交期）、机械（项目级、备件+售后、出口木箱）；话术里的产地取「所在城市 / 产地」字段，未套用模板时用通用话术。
- 一键起量（新手一条龙）：控制台「一键起量」按钮，输入产品+市场后自动跑完 联网找客户 → 批量补全联系方式+验证 → 按质量分排序生成待发邮件，最后停在发信队列的批量审批（未配置 Claude 时用演示数据跑通流程；发送始终等你过目）。
- 效果闭环 + 一键批量跟进：数据分析看板顶部「效果提示」用回复数据给出一句可执行结论（回复率最高的市场/最有效话术 + 多少客户到期未回复）；「一键批量跟进」（分析看板与发信队列均有入口，按钮实时显示到期数量）给已发过首封、超过跟进间隔仍未回复、未退订的客户批量排下一封序列跟进邮件，进入批量审批。
- 智能找联系方式：本地按域名+决策人生成多个候选邮箱（带置信度与模式，可一键设为主邮箱）；「AI 找联系人」按真实源优先（Hunter/Apollo/Dropcontact via 邮箱查找 Webhook，返回验证过的联系方式）→ Claude 推测决策人/候选邮箱/公司画像/匹配度 → 本地规则兜底，来源有徽章标注（真实验证/AI 推测/规则推测）。
- Claude 联网找客户：搜索页「Claude 联网找客户」按钮，用 Claude 内置联网搜索（web_search）按当前活动的市场/客户类型/产品/关键词，直接搜出真实存在的目标采购商并核验官网，解析进线索池走漏斗（需在设置配置 Claude API Key）。自动排除 alibaba/amazon 等平台与目录站本身。
- 粘贴/导入解析增强：一次粘贴尽量多抽公司——支持一行含多个 URL 自动拆分、CSV 表头自动识别跳过、全文域名兜底扫描（正文里任何真实域名都能补成线索），并自动跳过 google/linkedin/alibaba 等平台域名；散文行内夹域名时用域名反推干净公司名。
- 找相似客户：潜客详情「找相似客户」按钮，以选中这家为样本，配 Claude 时联网找同市场/同品类/相近规模的真实相似公司，未配 Claude 时用本地规则按其特征生成一批（清晰去重，展示名不含内部标记）。
- 官网一键深挖联系人：潜客详情「官网深挖联系人」按钮。桌面版先抓这家公司官网的首页，再顺着站内链接抓 About / Team / Contact / Impressum 等页（最多 4 页，认英德西法意葡多语写法），把正文交给你配置的任意 AI 找出真实采购决策人的姓名/职位/邮箱/电话，来源徽章「官网核实」（需配置 AI 引擎，不限服务商）。**每个邮箱必须能溯源**：模型没标 verified 也没给出处页面地址的一律丢弃，宁可这条线索没有邮箱，也不要一个按域名拼出来的地址。本地抓不到时（对方拦爬虫等）才退回 Claude 联网深挖。
- 一键批量补全联系方式：潜客队列「批量补全联系方式」按钮，对所有缺邮箱/待补全/新发现的线索依次跑「AI 找联系人」链路（真实源 Webhook→Claude→本地规则），带进度日志，省去逐条点击。
- 竞品渠道反查：搜索页「竞品渠道反查」，粘贴竞品的 Where-to-buy / 经销商列表 / dealer locator 页面链接，桌面版把页面抓回本地、由你配置的任意 AI 抽出他家所有经销商/分销商作为高意向线索进池（需配置 AI 引擎，不限服务商）。挂在竞品经销商页上的公司是被该品牌认证过的渠道商，信号强度仅次于海关提单，且不产生数据采购成本。注：经销商由地图控件动态加载的页面抓不到内容，换品牌的纯列表页（常见名称 Dealer List / 按国家分页）即可。
- 每日自动联网找新客户：Agent 任务的周期补量可勾选「联网找真实客户」，配合自动驾驶到周期用 Claude 联网搜真实客户补量（未配 Claude 或联网无果时自动降级到采集 Webhook/生成器）。
- Webhook 联调：每个渠道 Webhook 可一键测试连接（含状态码与延时），Webhook 模式下把邮件/WhatsApp/CRM 队列真实派发给外部服务，并记录活动日志。
- 自动驾驶：一键开启全流程自动流转——新线索自动补全验证、高分自动入队（遵守评分阈值/日上限/冷却期）、到期邮件批量发送并回传、跨渠道接力自动执行、客户回复自动生成 AI 草稿送审批。
- 流程规则：客户回复即自动取消剩余触达序列（回复即停）；询价/要样/砍价等意图自动推进商机到「询盘」；冷却期内不重复触达同一客户；审批通过即自动发送/派发。
- 界面体验：导航按「获客→触达→转化」流程分组并带待办徽标（未读回复/待审批/待发送）；所有操作即时 Toast 反馈；控制台新手引导清单五步上手；空页面提供下一步跳转按钮。
- 首次欢迎向导：全新用户第一次打开弹欢迎卡，给两条明路——「一键体验」用演示数据铺一批线索直接跑到发信队列看效果，或「填我的产品直接开始」聚焦到产品输入；看过一次不再弹。
- 今日待办工作台：控制台顶部把每天要处理的事聚成一屏——Agent 待审批 / 邮件待审批 / 已批准到期待发 / 新回复待处理 / 到期未回复（一键批量跟进），每项一键直达或直接处理；Webhook 模式且配了拉取回复 Webhook 时，标题栏还有「拉取新回复」一键从收件服务（n8n/IMAP）拉真实回信。全部清空时显示"今日暂无待办"。
- 优先联系名单：数据分析看板在市场/话术洞察下，按机会分排出「今天先追谁」Top5（已回复 &gt; 已打开 &gt; 高分，标注等级与成交概率），点任一行即选中该客户并跳转（有回信去收件箱，否则去潜客详情），把洞察直接变成行动。
- 效率工具：Ctrl+K 全局命令面板（搜客户/页面/动作直达）；深色模式一键切换并记忆；收件箱内直接手写快捷回复（邮件/WhatsApp 双渠道）；CRM 卡片点击弹出详情抽屉（改阶段/金额、看动态、跳会话）；数据分析支持 全部/近7天/近30天 时间范围。
- 资料补全：模拟联系人、邮箱规则、公司规模和置信度。
- 邮箱验证：基础格式验证和可发信状态流转。
- 开发信序列：首封、价值跟进、样品/案例、最后触达四封英文邮件。
- WhatsApp 开发：生成号码、WhatsApp 话术、wa.me 打开聊天链接和待确认队列。
- 发信队列：把高分潜客或单个潜客加入发送队列。
- 全渠道统一收件箱：把邮件与 WhatsApp 消息按客户汇聚成同一条时间线，标记客户回复、未读和渠道来源。
- 跨渠道接力：邮件未回 N 天自动转 WhatsApp 触达，WhatsApp 未覆盖回退邮件；客户一旦回复，该会话自动停止接力。
- AI 助手：客户回复后自动识别意图（询价/要样/砍价/交期/认证/拒绝等）、生成个性化回复建议、给出对话摘要与下一步动作，可一键复制或采用为回复。
- 回信风险识别：自动扫描客户来信中的风险事项（付款风险/疑似诈骗/制裁合规/知识产权/利润风险/样品滥用/信息不一致），分高中低三级、给出证据与应对建议，展示在收件箱 AI 面板与 Agent 热意向卡；识别到高风险时初轮应答护栏自动转人工。本地规则 + Claude 双引擎。
- 周期任务：Agent 任务可设为每天/每周/每月自动补充 N 个新线索，配合自动驾驶到周期自动执行一遍寻客漏斗，也可「立即补充一批」；真实部署走搜索采集 Webhook + 外部 cron。
- AI 引擎（多服务商）：在「设置 → AI 引擎」选「云端大模型」，服务商可选 Claude（Anthropic）、OpenAI ChatGPT，以及国产大模型 DeepSeek 深度求索 / 通义千问 Qwen / Kimi（Moonshot）/ 智谱 GLM，或「自定义」填任意 OpenAI 兼容接口的 Base URL——后者一套代码覆盖绝大多数大模型。填入对应 API Key 与模型名后，意图识别、回复建议、对话摘要、深度个性化写信升级为真实大模型；未配置或调用失败时自动降级为本地规则。注：只有「联网找客户」与「公司名→官网域名解析」还依赖 Claude 内置联网搜索——它们要的是「上网搜索」；前者也可改配 SerpAPI 直连（见数据源设置）。「竞品渠道反查」与「官网深挖联系人」已解除该限制：它们要的只是「读已知网址下的页面」，桌面版自行抓取后交给任意模型解析，抓不到时才退回 Claude 联网。浏览器版直连非 Claude 服务商可能遇跨域（CORS）限制，桌面版或经 n8n 代理不受影响。
- CRM 商机看板：线索 → 已触达 → 已回复 → 询盘 → 报价 → 成交 拖拽式管道，超期跟进标红、管道金额和成交率实时统计。
- 退信识别与自动拉黑（直连模式）：收件箱里不只有客户回信还有退信。IMAP 拉取时先判别——发件人（MAILER-DAEMON/postmaster/no-reply 等）、主题（英中文的"无法投递/退信/Undeliverable"等）、标准 DSN 头（`report-type=delivery-status`）、以及 `Auto-Submitted`（休假自动回复同样不该当客户回信）。判为退信的不入收件箱，改从正文的 `Final-Recipient` 抽出失败地址：`Status: 5.x.x` 是永久失败（地址不存在）立即拉黑，`4.x.x` 是临时失败（对方满了）只标记不拉黑——拉黑软退信会误伤正常客户。不认出来的话，一封 MAILER-DAEMON 会被当成"客户主动回信"自动建档、推进商机、开了 AI 自动应答还会去回复退信服务器，而真正的坏地址留在池里继续发。
- 计费接口的每日用量闸门：邮件日限一向很严，但 SerpAPI / Hunter 是按次真金白银计费的，而自动驾驶与周期补量会在后台静默调用——开着托盘常驻睡一觉可能醒来额度就烧光。现在两者各有每日上限（默认 50 / 100，可在「设置 → 数据源」调整），到顶只暂停调用不影响其它功能，次日自动重置；设置页实时显示今日已用次数。
- 本地海关提单库 + 按供应商反查（桌面版）：导入海关 CSV 时，**原始提单**会存进本机 `userData/customs.jsonl`（不进 localStorage——那里只有 5MB，几万条提单必爆；也不进备份 JSON）。攒下来之后就能做提单数据独有的那件事：**输入竞争对手的名字，列出所有从它进货的买家**——竞品官网上的经销商页是宣传，提单是交易记录。结果按进货次数排序（同样是竞品客户，买得多的更值得先打），可勾选后一键入池，走 admitProspects 同一个闸门，采购信号写明"从 X 进货 N 次 · 最近 YYYY-MM-DD"，初始分按进货次数加权。
  - 增量去重按「收货人+供应商+日期+HS+品名」哈希：同一份文件重复导入不翻倍，下季度的增量数据能并进来并刷新计数。
  - 刻意**不提供整库导出**——多数数据商的条款允许订阅者自用、禁止再分发，做了导出就等于给再分发开了通道。
  - 单行损坏只跳过该行，不毁掉整库。
- 修复：海关 CSV 只有「Country of Origin」一列时，原产国被误当作买家所在市场（巴西买家被标成 China，连累时区发送窗口、渠道建议与工具清单）。根因是列匹配函数在排除模式命中不到时会忽略排除条件再找一遍，对国家列这个回落是有害的——认不出目的国时留空反而正确，下游会退回活动配置的目标市场。
- 直连找客户与补邮箱：「设置 → 数据源」填 SerpAPI Key 即可联网找客户（直接调 serpapi.com，结果按域名去重并剔除平台/目录站），填 Hunter Key 即可补全采购人邮箱——都不再必须经 n8n 中转。Hunter 返回的地址按置信度分级：≥80 才当真实源（可直接发），低于此值标为推测、照样被发送闸门拦下（domain-search 返回的是"公开网页上找到的地址"，不等于验证过，不能一律放行）。留空则各自回落到对应 Webhook。仅桌面版可用（浏览器模式会被 CORS 拦）。
- 备份自动脱敏 API Key：导出备份、每日自动备份、恢复前的自动备份三处都会抹掉 AI 引擎 / SerpAPI / Hunter 的 Key——备份 JSON 本来就是要发给客服、放网盘、跨机搬迁的，Key 混在里面等于随手外发凭据。恢复时会保留本机已填的 Key，不会因为恢复一次就要重配。（SMTP/IMAP 密码从来不在这里，它们在主进程加密存着。）
- 本地模拟模式不给 A/B 结论：本地模式的"打开"是按哈希生成的假数据，A/B 面板此时只展示数字并明确标注不可据此判断，切到直连或 Webhook 真实发信后才给结论——拿随机数改文案是负收益。
- Gmail / Outlook 识别提示：这两家已强制 OAuth2，普通「授权码 + SMTP/IMAP」大概率连不上。填入对应主机时直接给出说明与替代方案（改用企业邮箱，或走 Webhook 在 n8n 侧用 OAuth 凭据），避免用户反复试错到怀疑软件坏了。
- 内置收发信（直连模式，免自建 n8n）：运行模式从「本地模拟 / Webhook」两档扩为三档，新增「直连」。填一组 SMTP、一组 IMAP，应用就能真发真收——发信走主进程 nodemailer、收信走 imapflow，都是裸 TCP+TLS，浏览器做不到所以只有桌面版有。**密码全程留在主进程**：用 safeStorage 加密写入 userData/mail.dat，渲染层只能读到"主机/账号/配没配"的摘要，密码既不进 state 也不进备份 JSON，导出备份发给客服不会泄露；凭据文件损坏时静默回退未配置、不崩溃。保存时密码留空表示"不改"，调端口不用重输授权码。错误分型翻译成"你该改什么"（认证失败 → 多半填了登录密码而非授权码；ECONNREFUSED → 端口填错；ENOTFOUND → 地址拼错；ECONNRESET → 端口与加密方式不匹配）。直连与 Webhook 可混用：发信收信直连、找客户走 n8n 完全可以。发送分派收敛到单一入口，直连模式下逐封回执——一封认证失败不会把整批误标成已发送。
- 各市场外贸工具清单：搜索页顶部按活动的「目标市场」逐个给出该市场怎么打——海关数据可得性（美国/印度/拉美/俄罗斯有提单级，欧盟与日韩因隐私法根本查不到）、去哪找客户（ThomasNet / Europages / Kompass / wlw / IndiaMART / Yandex / Dubai Chamber 等）、用什么补邮箱、怎么触达、以及该市场特有的坑（欧盟 CE-REACH 是入场券、非洲信用风险要 T/T 预付、巴西先问 NCM、俄罗斯先确认收款路径、日本常走商社而非直接进口）。同一区域的多个市场合并成一张卡并标出命中哪几个；未收录的市场明确说明按默认处理。界面上注明第三方服务与价格随时会变、以各自官网为准，且本软件与任何一家无关联。
- 按市场选渠道：WhatsApp 不是通用渠道。新增市场→渠道映射表（与多语言、时区表同构）：美国/加拿大/澳新走「邮件 + LinkedIn」、欧盟与英国因 GDPR 默认只走邮件、俄语区标 Telegram、越南标 Zalo、日韩标邮件 + LINE/KakaoTalk、缅甸标 Viber；拉美/非洲/中东/南亚东南亚/土耳其为 WhatsApp 主力市场。自动路径（一键起量、Agent、自动驾驶、接力）对不适合的市场不再生成 WhatsApp；潜客详情显示该市场推荐渠道与理由，用户在详情页手动点仍可越过判定（他比表更懂那单客户）。未识别的市场保守放行，不一刀切。
- 邮件 + WhatsApp 协同模式：收件箱顶部可在「接力」和「协同」间切换。接力＝先只发邮件、超时未回才转 WhatsApp（最保守）；协同＝入队时邮件立即排、WhatsApp 排在 N 天后（默认 2 天），话术引用那封邮件的主题与日期——它的任务不是二次推销，而是用到达率更高的渠道把邮件从垃圾箱里捞出来。两条各自独立推销像群发机器人，后者引用前者才像认真跟进的销售。协同这条永远是「待人工确认」，且同样要过市场判定；客户从任一渠道回复，两边都停。
- 后台常驻（桌面版）：「设置 → 后台运行」两个开关——①关闭窗口后收进系统托盘、自动驾驶继续工作，托盘图标右键可「完全退出」；②开机自动启动，带 `--minimized` 静默起在托盘不弹窗（需先开启第一项，否则起一个马上被关掉的窗口只会打扰人）。首次隐藏到托盘会弹一次气泡说明，避免用户以为程序没关掉。偏好落在 userData/background.json，读坏了静默回落到"都关"不影响启动。机器关机仍会停——真 7×24 需要 n8n + 外部 cron。
- 首封主题行 A/B：首封自动分成两种写法——A 品类卖点式（供应商自述）、B 点名公司的提问式（买家视角），按线索 id 稳定哈希分配，同一条客户永远落在同一边，重建序列/切换活动/重新入队都不漂移。分析看板按变体统计发出/打开/回复/回复率；每个变体不足 20 封时明确提示"样本不够，先继续发别急着改话术"，差异小于 3 个百分点时提示"主题不是当前瓶颈"——不在小样本上给结论。
- 报价单一键发给客户：报价单生成后可直接排进发信队列——明细以纯文本内嵌正文（不用 PDF 附件：冷发带附件明显拉低送达率，而报价这封往往是询价后第一封实质回复，进垃圾箱代价最大），走与开发信同一个预检闸门，未验证邮箱照样 ⛔ 拦下，且仍停在待审批等你过目。同一张报价单不会重复排队。要正式 PDF 的场景仍可「打印 / 存 PDF」。
- 报价单历史：管理页新增报价单面板，已生成的报价随时打开、重发或存 PDF，并标出未发送 / 待审批 / 已发出三种状态。
- 数据分析看板：全流程漏斗（线索 → 有联系方式 → 已入队/触达 → 送达 → 打开 → 回复 → 询盘，一屏看完整转化，合并了原管理页的线索阶段漏斗）、邮件/WhatsApp 渠道对比、双渠道接力效果、市场表现、话术回复率排行，北极星指标为有效询盘数/月。
- 跟进任务：按 3、7、14 天生成自动跟进任务。
- 管理后台：轻量多活动管理、自动化任务中心、审批中心、渠道账号、规则配置（线索阶段漏斗已合并进分析页的全流程漏斗）。
- 轻量多活动：可新建/重命名/删除多个开发活动（如摩托配件、汽配、电子各一套），每个活动保存**完整配置**（产品/市场/客户类型/卖点/认证/品类模板/日限），点活动名即整套恢复到控制台——切换不再只换产品导致卖点串味。线索按 campaignId 归属，活动列表的线索/队列/回复数是**按活动实时统计**的真实数字，删除活动会把其线索转移到其它活动不丢。
- 真实管理面板：审批中心从真实待办汇总（Agent 待审批卡 / AI 草稿 / WhatsApp 待确认 / 邮件待批量发送），每项点击直达处理页；渠道账号显示真实状态（是否接入 Webhook + 最近测试结果 + 今日实际发送量/日限）；任务中心标注真实触发方式（手动「运行待执行」或自动驾驶），不再有写死的假排期。
- 导出：搜索式、潜客、发信队列、WhatsApp 队列和完整 JSON 数据。
- Webhook 接口位：预留搜索采集、邮箱补全/验证、发信、WhatsApp Business 和 CRM 同步接口。

## AI 自动获客 Agent

「AI Agent」是系统的总入口——五步闭环：任务解析 → 自动寻客 → 触达审批 → 自动开发 → 意向移交。

1. **下达任务**：用一句话描述目标客户。配置了 Claude API（设置 → AI 引擎）时由大模型解析并自动扩展英文行业关键词与当地术语；未配置时用本地规则解析（国家、客户类型、日上限、渠道均可识别）。
2. **任务卡片确认**：解析结果以可编辑卡片回显（产品/市场/类型/关键词/上限/渠道），确认后才执行，避免理解偏差浪费额度。同时选择审批模式——逐条审批（默认，冷启动推荐）/ 批量抽审 / 全自动（自动开启自动驾驶）。
3. **自动寻客**：确认后生成搜索任务；导入线索（粘贴 / Webhook / 演示数据）即触发过滤漏斗：原始抓取 → 画像匹配（市场过滤）→ 验证 → 去重 → AI 评分入围（受每日上限约束）。
4. **触达审批**：每个入围客户生成审批卡——是谁、为什么值得开发（评分因子）、邮件首触与 WhatsApp 话术预览；逐条通过 / 跳过，或一键全部通过。抽审与全自动模式自动通过入队。
5. **自动开发（AI 初轮应答，带护栏）**：在「AI Agent → 第 4 步」开启后，客户回复标准问题（发目录/要样品/问 MOQ/交期/认证/一般价格）时 AI 自动答复，并明确告知详细报价由销售同事跟进；可填写「产品知识库/FAQ」喂给 AI。三重护栏：**涉及具体报价折扣、账期、独家代理、合同条款等敏感话题一律不擅自答复，立即转人工**；客户 opt-out（unsubscribe/退订等）即时加入黑名单并取消全部待发触达、之后不再入队；所有 AI 应答与转人工动作留痕在面板可查。配置 Claude API 时回复内容由大模型基于知识库生成，否则用护栏模板。
6. **意向移交**：客户回复后按意图自动分级——询价/要样/MOQ/交期/认证及被转人工的敏感话题为 🔥 热意向（卡片附对话摘要，点「接管会话」直达收件箱）；回复未询价为 🌤 温（培育）；已读不回、明确拒绝与 opt-out 为 ❄️ 冷。有足够数据时给出"效果回流"建议（哪个市场回复率显著更高，建议倾斜）。

合规说明：本系统不做任何协议破解或绕过反爬的抓取；线索来源为公开信息的人工/Webhook 导入，「演示数据」仅用于体验流程。

## 使用

直接用浏览器打开 `index.html`。

推荐流程：

1. 在「控制台」填写产品、市场、客户类型和卖点。
2. 点击「生成开发计划」得到搜索任务。
3. 打开搜索任务，复制真实公司官网、LinkedIn 公司页、邮箱、电话或 CSV 行。
4. 回到「搜索」里的「搜索结果导入」，粘贴结果并点击「解析为线索」。
5. 在「潜客」里审核线索、补全资料、验证邮箱和生成 WhatsApp。
6. 在「邮件」「WhatsApp」「队列」里生成触达内容、加入队列和导出。
7. 在「管理」里保存活动、运行任务、审批 WhatsApp 队列、配置自动化规则和导出管理数据。

## 管理后台

「管理」模块用于把自动化流程变成可运营的管理系统：

- 活动管理：保存当前开发活动，切换不同产品/市场活动。
- 自动化任务中心：管理搜索采集、资料补全、邮箱/号码验证、话术生成、入队限流、CRM 同步等任务。
- 审批中心：集中处理 WhatsApp 待确认消息、话术审核和低分线索风控。
- 渠道账号：查看 Email、WhatsApp、Search API、CRM 的使用量和接入状态。
- 自动化规则：配置邮件日上限、WhatsApp 日上限、最低线索评分、冷却天数、WhatsApp 是否必须审批。
- 线索阶段漏斗：查看新发现、已丰富、邮箱有效、已入队、已回复等阶段分布。

## 自动驾驶（全流程自动化）

顶栏「自动驾驶」开关开启后，系统按固定节拍（演示模式每 8 秒一拍，对应真实系统的小时级调度）自动执行整条获客流水线，无需逐步点击：

1. 新导入线索自动补全资料 + 验证邮箱/号码
2. 达到评分阈值的线索自动加入发信队列（遵守每日上限与冷却期）
3. 到期邮件批量发送（Webhook 模式走真实发信服务），并自动生成送达/打开回传
4. 已审批的 WhatsApp 自动发送/派发
5. 跨渠道接力自动执行：邮件未回转 WhatsApp、WhatsApp 未覆盖回退邮件
6. 客户回复后自动生成 AI 回复草稿，进入审批中心等待人工放行

**发送始终需人工审批**：自动驾驶只负责 找客户→补全联系方式→验证→评分→把高分线索备到「待发送 / 待审批卡」，绝不自动发出。发送由人工触发——Agent 审批卡「通过并发送」、队列「发送今日到期」、或审批中心「全部通过」。Agent 审批模式为 逐条审批 / 批量审批（均需人工过一遍，已移除全自动发送模式）。

事件驱动的自动规则（无论自动驾驶是否开启都生效）：

- **回复即停**：客户一回复，其剩余未发的邮件序列和 WhatsApp 队列自动取消，不再打扰。
- **意图推进商机**：AI 识别到询价/要样/砍价/交期/MOQ/认证等意图时，商机自动推进到「询盘」（北极星指标自动增长）；识别到拒绝则转入培育名单。
- **冷却期**：同一客户在「自动化规则」设定的冷却天数内不会被重复加入触达队列——这也让自动驾驶默认「邮件先行，WhatsApp 只走接力」，符合合规理念。
- **导入即处理**：自动驾驶开启时，粘贴导入搜索结果后立即自动补全、验证、入队。

「管理」页的自动化任务中心也已接入真实执行：「运行待执行」会依次真实运行采集（Webhook 模式）、补全、验证、话术、入队、CRM 同步，并显示每项的实际处理结果。

## AI 客户评分

「潜客」列表和详情面板会展示每个客户的 AI 成交概率与优先级：

- 加权因子模型：基础分 + 官网真实性、邮箱质量、WhatsApp 号码、采购角色/信号、客户类型匹配、资料置信度，以及权重最高的互动信号（已回复 > 已打开 > 已触达）。
- 成交概率与分级：综合得分映射为 0–99% 成交概率和 A/B/C/D 优先级，支持「高分客户优先触达」。
- 可解释：详情面板逐项列出每个因子的加分与短板（如「缺邮箱」「尚未触达」），评分随触达和客户回复实时变化。

本地为规则加权实现；接入真实数据（海关进口记录、企业库、行为回传）后，同一套因子框架可替换为机器学习模型输出。

## 全渠道统一收件箱与跨渠道接力

「收件箱」模块把发信队列（邮件）、WhatsApp 队列和客户回复汇聚到同一条客户时间线，是本系统的核心差异点：

- 会话列表：按客户聚合，显示已用渠道、是否已回复、未读数、是否已接力。
- 客户时间线：邮件、WhatsApp、客户回复按时间合并，完整还原沟通历史。
- 跨渠道接力规则：
  - 「邮件未回自动转 WhatsApp」：对已发邮件但未回复、且有号码的客户，自动生成 WhatsApp 接力触达（默认仍走「待人工确认」，遵守审批规则）。
  - 「WhatsApp 未覆盖回退邮件」：对只在 WhatsApp 触达、但有邮箱的客户，自动补一封接力邮件。
  - 未回天数可配置；把天数设为 0 可立即演示接力。
  - 客户一旦回复，会话标记「已回复」，自动停止对该客户的接力。
- 演示：每个未回复会话可点「模拟客户回复」验证「回复即停」逻辑，也可对单个会话手动「转 WhatsApp 接力 / 转邮件接力」。

接入真实 WhatsApp Business / 邮件 API 后，接力生成的队列条目可直接通过「设置」里的 Webhook 交给模板消息服务或 SMTP 服务发送。

### AI 助手（意图识别 + 回复建议）

当会话收到客户回复时，收件箱时间线会出现「AI 助手」面板：

- 意图识别：按关键词优先级（拒绝 > 议价 > 样品 > 询价 > 交期 > MOQ > 认证）判定客户最新意图并给出置信度，时间线里的每条客户回复也会标注意图标签。
- 对话摘要：一句话概括触达次数、回复数、最新意图和当前商机阶段，并给出下一步动作建议。
- 回复建议：按意图和活动信息（产品、卖点、认证、署名）生成个性化英文回复，可「复制建议」或「采用为回复」——采用后按客户回复的渠道自动加入邮件或 WhatsApp 队列。

默认是规则启发式实现；在「设置 → AI 引擎」切换到 Claude API 并填入 Anthropic API Key（仅存本机浏览器 localStorage，不上传任何服务器）后：

- 客户回复会自动发给 Claude 做**语义级**意图判断（结构化输出保证结果可直接入库），面板会显示「Claude · 模型名」来源徽章，摘要与建议回复由真实大模型基于完整对话上下文生成。
- 邮件页新增「Claude 深度写信」：按客户公司、市场、角色、采购信号生成整套 4 封个性化开发信，替代模板填空。
- 模型可选 Claude Opus 4.8（默认，最强）/ Sonnet 5 / Haiku 4.5；「测试连接」一键验证 Key 与延时。
- 浏览器直连 Anthropic API（带官方 `anthropic-dangerous-direct-browser-access` 头）；任何调用失败都会记录日志并自动回退本地规则，不阻塞流程。

获取 API Key：https://platform.claude.com/ → API Keys。注意：Key 属于敏感凭证，本模式适合个人/本机使用；团队部署建议改为服务端代理转发。

## CRM 商机看板

「CRM」模块把潜客变成可管理的商机管道，是承接收件箱的「管客户」环节：

- 六阶段看板：线索 → 已触达 → 已回复 → 询盘 → 报价 → 成交，拖拽卡片即可推进商机。
- 自动推进：加入邮件/WhatsApp 队列自动进入「已触达」，客户回复自动进入「已回复」，无需手动同步。
- 超期提醒：卡片显示下次跟进日期，超期未跟进标红，触达后未安排跟进标黄。
- 管道统计：总商机、询盘及以上、报价中、成交率、在谈金额、超期跟进数实时汇总；每列显示商机数与预估金额。
- 导出：一键导出管道 CSV（公司、阶段、评分、金额、联系方式、下次跟进）。

预估金额目前按线索评分自动生成，接入真实 CRM（Twenty、HubSpot 等）后可通过 Webhook 双向同步真实金额与阶段。

## 数据分析看板

「分析」模块把触达数据变成可决策的运营指标：

- 北极星指标：有效询盘数/月（进入询盘及以上阶段的客户数），而非发送量。
- 渠道漏斗：触达 → 送达 → 打开 → 回复 → 询盘，按客户去重并显示各级环比转化率。
- 渠道对比：邮件与 WhatsApp 各自的触达/送达/打开(已读)/回复率并列，直观体现双渠道差异。
- 双渠道接力效果：对比单渠道与双渠道（接力覆盖）客户的回复率，量化「双渠道回复率高一个量级」的产品卖点。
- 市场表现：按市场统计触达、回复、询盘和回复率排名。
- 话术回复率排行：按邮件/WhatsApp 模板统计发送与回复率，沉淀公司级高效话术。

送达率与打开率在本地模拟中由「模拟送达/打开回传」按钮按线索质量生成；接入邮件服务商与 WhatsApp Business API 后，这些数据由真实的 delivery / open / read 回调经 Webhook 写入。

## 接入真实自动化

当前版本默认是本地管理系统，不会绕过浏览器或平台规则去抓取公司，也不会真实发送邮件/WhatsApp。没有接 API 时，它负责生成搜索任务、解析导入结果、管理线索和队列。

要接真实流程，可以在「设置」里切到 Webhook 模式，并填入：

- 搜索采集 Webhook：接 Google Custom Search、SerpAPI、Bing Search API、Apify、n8n 或 Activepieces。
- 邮箱查找/验证 Webhook：接 Hunter、Apollo、Dropcontact、ZeroBounce 或 NeverBounce。
- 发信 Webhook / SMTP 服务：接自建发信服务、n8n SMTP、SendGrid、Mailgun 或企业邮箱 API。
- WhatsApp Business Webhook：接 WhatsApp Business Platform、360dialog、Twilio、WATI、n8n 或 Activepieces。
- CRM 同步 Webhook：接 Twenty、悟空 CRM、EspoCRM、HubSpot 或自定义数据库。
- 拉取回复 Webhook：接 n8n IMAP/邮箱服务，把真实客户回信拉进收件箱（见下方「拉取回复接口」）。

### 连接测试与派发

每个 Webhook 输入框下有「测试连接」按钮：点击会向该地址 POST 一个 `{"type":"<连接名>","ping":true,...}` 的探测请求，并在旁边显示状态（正常/失败/未配置 + HTTP 状态码 + 延时）。

「Webhook 派发」面板的「派发待处理队列」按钮：

- Webhook 模式下：把待发送邮件批量交给发信服务、已审批 WhatsApp 交给 Business API、全部潜客同步到 CRM，成功后才把队列条目标记为已发送；失败则保留原状态并记录错误。
- 本地模式下：仅做本地模拟发送。
- 所有调用（含搜索采集与连接测试）都记录在下方的「Webhook 活动日志」，可追溯地址、状态码和耗时。

- CRM：`{ "type":"crm", "prospects":[{company,market,email,phone,stage,score}] }`

> 浏览器直连 Webhook 受同源策略限制，目标地址需允许跨域（CORS），或在自动化平台（n8n/Make/Activepieces）侧开启。

      "website": "example.com",

### 真实数据源接口（搜索采集 Webhook）

在「设置 → 搜索采集 Webhook」填入自动化平台（n8n / Make / Activepieces）或自建服务的地址后，系统在寻客/周期任务时会向该地址 POST 一个搜索请求，期望同步返回潜客数组。

系统发出的请求载荷（`campaign` 为当前活动配置，`searchPlan` 为已生成的搜索式数组）：

```json
{
  "type": "search",
  "sentAt": "2026-07-05T00:00:00.000Z",
  "campaign": {
    "product": "stainless steel water bottle",
    "markets": "United States, Germany",
    "customerType": "进口批发商",
    "valueProps": "...",
    "dailyLimit": 20
  },
  "searchPlan": [
    { "channel": "Google", "market": "United States", "query": "\"stainless steel water bottle\" (\"importer\" OR \"distributor\") \"United States\" -alibaba" }
  ]
}
```

期望返回（与上文"Webhook 返回潜客"结构一致，`prospects` 数组即可）：

```json
{
  "prospects": [
    { "company": "Acme Drinkware", "market": "United States", "website": "acmedrinkware.com", "email": "buyer@acmedrinkware.com", "source": "SerpAPI", "score": 80 }
  ]
}
```

#### n8n 示例工作流

- **Google/SerpAPI 找官网**：Webhook 触发 → HTTP Request 调 SerpAPI（`q` 用 `campaign.product`+`campaign.markets` 拼搜索式，或直接复用传入的 `searchPlan[].query`）→ Function 节点解析 organic_results 的 title/link 成 `{company, website, source:"SerpAPI"}` → Respond to Webhook 返回 `{prospects:[...]}`。
- **海关数据核验进口商**：Webhook → HTTP Request 调海关数据服务（如 ImportGenius / 采购商数据 API）按品类查有真实进口记录的买家 → 映射成 prospects（`buyingSignal` 写"有 N 条进口记录"）→ 返回。
- **Apollo/Hunter 补联系人**：把上一步的 website 传给邮箱补全 Webhook（Apollo People Search / Hunter Domain Search）→ 返回 `contactName/role/email` 合并进 prospects。这一步也可直接用潜客详情的「AI 找联系人」触发邮箱查找 Webhook。

> 合规提醒：Webhook 侧对接的第三方数据源需自行确保数据来源合法、遵守其服务条款；系统只负责把返回的公开信息接进漏斗，不做任何抓取或反爬绕过。浏览器直连需目标地址允许跨域（CORS），或在自动化平台侧开启。

### 拉取回复接口（真实客户回信入口）

配置「设置 → 拉取回复 Webhook」后，收件箱的「拉取回复」按钮（或自动驾驶每分钟一次）会 POST：

```json
{ "type": "inbound", "sentAt": "…", "since": "2026-07-05T02:00:00.000Z" }
```

期望返回 `since` 之后的新回信（首次拉取 `since` 为 null，返回近期全部即可）：

```json
{
  "replies": [
    {
      "from_email": "buyer@acmeimports.com",
      "from_name": "Alex Buyer",
      "channel": "email",
      "text": "Please send your FOB price list and MOQ.",
      "at": "2026-07-05T01:23:00.000Z",
      "company": "Acme Imports"
    }
  ]
}
```

系统按邮箱（主邮箱/候选邮箱）匹配线索，其次按公司名；都匹配不上会自动补建一条「回信导入」线索，绝不丢回信。入库后自动联动：回复即停序列、退订进黑名单、意图识别推进 CRM、风险扫描、AI 初轮应答（试运行模式下先存草稿等审批）。

**n8n 示例工作流（IMAP 收件）**：IMAP Email 节点监听你的外贸邮箱收件 → Function 节点把新邮件存入一个表/静态数据（记录 from/subject/text/date）→ Webhook 节点收到本系统的 `{type:"inbound", since}` 请求时，过滤出 `date > since` 的记录映射成 `{replies:[…]}` 返回。注意在 n8n 的 Respond to Webhook 上开启 CORS。
