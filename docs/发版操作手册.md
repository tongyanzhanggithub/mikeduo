# 觅客舵 · 发版操作手册

---

## 1. 一次发版的完整动作

```bash
# ① 改版本号：package.json 的 "version"

# ② 代码走查（八项静默失效检查，退出码 1 = 有问题）
node tools/audit.mjs

# ③ 检查内置数据集是不是该重建了（退出码 1 = 必须重建）
node tools/check-data-age.mjs

# ④ 跑测试
npm test

# ⑤ 重新生成图标（只在改过 tools/make-icon.mjs 时需要）
npm run icon

# ⑥ 构建前端 + 打 NSIS 安装包
npm run dist
```

### 关于第 ③ 步：内置数据集必须随版本重建

`data/` 下三份是**快照**，不是实时查询。其中制裁名单最要紧——
**用一份过期名单做合规判断，比不做更危险**：不做的话用户知道自己没查，
用旧名单查完显示「未命中」，他会以为自己是安全的。

| 数据 | 提示线 | 告警线 | 重建命令 |
|---|---|---|---|
| 制裁与实体名单 | 90 天 | 180 天 | `node tools/build-screening.mjs` |
| 采购官联系人库 | 180 天 | 365 天 | `node tools/build-tenders.mjs` |
| HS 编码目录 | 730 天 | 1460 天 | `node tools/build-hscodes.mjs` |

阈值按各自的真实更新频率定：OFAC 几乎每周都在动，HS 五年才修订一次。

重建要用到原始数据集（395 MB，不在仓库里，路径见 `docs/交接与待办.md`）
和本机的 python。**没有原库就发不了带新名单的版**——这是发版的硬前置。

应用里也有对应的兜底：超过提示线时合规面板会显示提醒，超过告警线时用红色，
并且**即使筛查未命中也会露出提醒**——那恰恰是最危险的一刻。

产物在 `dist-desktop/MiKeDuo-Setup-v1.0.0.exe`。

> `npm run dist` 已经内置了 `npm run build`（src/ → app.js 并打版本戳），不要跳过直接跑 electron-builder，否则装出来的是旧界面。

**算校验值**（发货消息里给出，专业感很值钱）：

```bash
node -e "const c=require('crypto'),f=require('fs');console.log(c.createHash('sha256').update(f.readFileSync('dist-desktop/MiKeDuo-Setup-v1.0.0.exe')).digest('hex'))"
```

## 2. 自动更新的更新源

`package.json` 的 `build.publish` 目前是占位：

```json
{ "provider": "github", "owner": "REPLACE_ME", "repo": "mikeduo-release" }
```

首次配置：

1. 建一个 GitHub 仓库（**可以是私有**，但私有仓库的自动更新需要 token，起步阶段建议用公开仓库只放 release 文件，不放源码）
2. 把 `owner` 换成你的 GitHub 用户名，`repo` 换成仓库名
3. 生成一个有 `repo` 权限的 token，本机设环境变量 `GH_TOKEN`

之后发布：

```bash
npm run dist -- --publish always
```

electron-builder 会自动创建 draft release、上传 exe 与 `latest.yml`（updater 靠这个文件比对版本）。**去 GitHub 把 draft 改成 published，用户才收得到。**

## 3. 打 tag 与写 release notes

```bash
git tag -a v1.0.1 -m "v1.0.1"
git push origin v1.0.1
```

Release notes 写给用户看，不是写给自己看：

```
### 修了
- 发信队列在 1366 宽屏下横向滚动的问题
- 阿里企业邮箱 SMTP 授权码报「认证被拒」时的提示改成了获取路径

### 新增
- 潜客列表新增「待验证」筛选，一眼看到哪些线索堵在验证上

你的数据不受影响，更新后原样还在。
```

## 4. 更新服务到期（首年免费之后）

- 应用读激活信息里的**签发日**，超过 365 天时「检查更新」返回到期提示
- 到期只停更新推送，**不影响任何现有功能**——买断就是买断，这条不能含糊
- 续订 ¥199/年：用户付款后，用**同一个机器码**重新出一次码，签发日填当天

```bash
node tools/gen-key.mjs 7F3A-K2M9-QX41-B8CD pro 2027-08-05
```

用户粘新码 → 更新服务到期日往后推一年，数据与档位不变。

## 5. 发版前检查清单

- [ ] `node tools/audit.mjs` 退出码为 0（无静默失效类问题）
- [ ] `node tools/check-data-age.mjs` 退出码为 0（内置数据集未过告警线）
- [ ] `npm test` 全绿
- [ ] `package.json` 版本号已改（三处会自动同步：关于页、诊断日志、安装包文件名）
- [ ] 在一台**干净的 Windows**（最好是虚拟机）里装一遍：能装、能开、能激活
- [ ] 覆盖安装老版本：数据没丢、激活状态还在
- [ ] 杀软误报自查：360 / 火绒 / Defender 各扫一遍，误报就在发货说明里附「添加信任」路径
- [ ] 1366×768 分辨率下全页无横向滚动
- [ ] 深色模式全页走查（易漏：图表、徽章、航程条）
- [ ] SHA-256 校验值已算好、已写进发货消息

## 6. 出事了怎么回退

用户装了坏版本时：

1. GitHub 上把这个 release 删掉或标记 pre-release（updater 立刻停止推送）
2. 把上一版的 exe 重新上传为 latest release
3. 给已经更新的用户直接发上一版安装包，覆盖安装即可（数据在 userData，不受影响）

**永远不要靠"用户自己回滚"**——他们不会，只会退款。
